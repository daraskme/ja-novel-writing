# 評価ラウンド 1（2026-09-19）

同じ依頼を、スキルあり（with_N.md）とスキルなし（base_N.md）で Codex CLI（gpt-6-astra、reasoning medium）に生成させ、由来を伏せて別コンテキストの Codex に読み比べさせた。点数と「AI っぽいか」の判定は求めず、引用つきの選好と誤りの指摘だけを求めた。

| 依頼 | 判定での A / B | 選好 | 由来 |
|---|---|---|---|
| 1 掌編「言えなかった一言」 | A=with, B=base | A | スキルあり |
| 2 饒舌な一人称コメディ | A=base, B=with | B | スキルあり |
| 3 直球の告白場面 | A=base, B=with | A | スキルなし |
| 4 AI 臭の推敲（「たった四文字」の罠入り） | A=with, B=base | A | スキルあり |

- 依頼 3 の敗因: スキルあり版は二人に固有の記憶（卵焼き）が評価された一方、結びが軽い笑い（置き忘れた卒業証書）に着地し、依頼が求めた「胸が熱くなる」余韻が弱まった。→ SKILL.md と prose-core 10 節に「結びを含む読後感が、依頼の約束を満たしているか確かめる」を追加（検証レビュー 2 の指摘で、笑いや静かな収束を排除しない弱い形にした）。この修正で選好が変わるかは未検証。二作品の比較だけでは、総括回避が敗因だったという因果までは確定できない。
- 依頼 4: スキルあり版は「ありがとう」が五文字であることを明示して処置した（スキルなしは黙って削除し、展開まで改変）。「二人が微笑み合う穏やかさは残す」と方針は述べたが、「小さく頷いた」「静かに」「いつの間にか」など個々の箇所と fix / keep の対応は示さなかった。→ SKILL.md の revise 手順に「lint が挙げた箇所は一件ずつ fix / keep を決め、keep は声・意味・速度・修正範囲のどれを守るかで判断する」を追加。勝因は修正範囲の遵守なので、定型語を一律に締める規則にはしない。
- lint の差: 依頼 1 は た止めの最長連続 13 → 6、依頼 3 は身体反応の定型 5.3/1000 字 → 警報なし。
- 限界: 4 件・各 1 試行・生成も判定も同一モデル。傾向の確認であって証明ではない。evals/evals.json の 9 件で、モデルと試行数を増やして繰り返すこと。

実際に使った依頼文（スキルあり／なしの前置きを含む）と判定用の依頼文は `prompts/` にある。生成時のスキルは、Codex レビュー 1 を反映した直後の版（レビュー 2 の反映前）。
