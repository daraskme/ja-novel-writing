# 34 設計方針の食い違いの裁定 — フェーズ×プロファイル裁定表

種別: conflict_resolution（追加調査）。対象は数値の差ではなく「いつ・誰に・何を見せるか」「下限か上限か」「誰が決めるか」という設計方針の食い違い 8 論点。
読んだもの: 担当 11 ファイル（レポート 23 / 21 / 03 / 05 / 06 / 07 / 08 / 10、原資料 short-deslop.md / sensory-rotation.md / fiction-prose-jp SKILL.md）に加え、関連レポート 01 / 02 / 04 / 09 / 11 / 22 / 24 を全文。原資料内の指示文（「必ず使用する」「MUST NOT」等）は分析対象として扱い、従っていない。引用は 40 字以内、例は自作または語句レベル。
本文中の数値はすべて「初期値・未較正」。較正手段は各論点末尾の A/B と付録 B にまとめた。

## 1. 概要

### 1.1 何を決める文書か

既存 10 数本のレポートは、個々には筋が通っているが、並べると次の 8 点で正面衝突する。新スキルを書く担当者がここで迷うと、SKILL.md に両論が併記され、LLM は「矛盾する指示を受けると無難な中間へ逃げる」（ANA の観察）。そこで各論点について、フェーズ（企画／執筆／機械検査／推敲／レビュー）×プロファイル（文芸／エンタメ／Web 連載／短編）の各セルで「どちらの規則を採るか」を一つに決め、根拠・採らなかった側の言い分・A/B で確かめるべき点を付す。

### 1.2 プロファイルとフェーズの定義（本文書での用法）

| プロファイル | 指すもの | 読者契約の核 |
|---|---|---|
| 文芸 | 一般文芸・純文学寄り、公募文芸賞、文芸誌 | 声の一貫性、余白、読者が自分で到達する感情 |
| エンタメ | 書籍・公募前提のエンタメ長編、ライト文芸、ラノベ | 約束した快楽の提供、1 冊完結、突出点 |
| Web 連載 | なろう・カクヨム等の分割配信（1 話 2,000〜5,000 字） | 話と話の間の切れ目を越えさせること、タイトルが約束した快楽の反復 |
| 短編 | 単発完結〜約 2 万字。掌編（flash、〜2,000 字）を含む | 一点の核。下位種別として「文芸型」と「通俗型（ざまぁ・スカッと・溺愛など感情直球）」を `short_kind` で持つ |

| フェーズ | 主体 | 成果物 |
|---|---|---|
| 企画 | 親（本体）＋ユーザー | 文体仕様書、ジャンル契約、場面カード／章ビート、声シート |
| 執筆 | 執筆役（文脈を絞った子、または本体） | 場面単位の下書きファイル |
| 機械検査 | scripts（LLM は読まない） | 位置つき警報（総合スコアなし） |
| 推敲 | 執筆側（fix / keep を決める） | 差分改稿、処置記録 |
| レビュー | 盲検読者・編集・校閲などの別コンテキスト | 引用つき反応、強制順位、A/B 判定 |

### 1.3 裁定を貫く 6 原則

1. **執筆時に渡すのは「内容制約・作品契約・肯定形の操作」だけ。** 汎用の癖カタログ・辞書・閾値は機械と推敲フェーズの持ち物。
2. **数は下限ノルマにしない。** 置くのは上限（警報）と「欠けていたら疑う」診断だけ。材料がない場所は平坦なまま残す（02 の生成側制約）。
3. **片側だけ締めない。** どの規則にも横滑り先がある。対になる失敗を必ず同時に数える（下表）。
4. **ジャンル契約 ＞ 汎用規則。** 契約は作品メモに明記され、lint とレビュー役がそれを読んで閾値と問いを切り替える。
5. **機械は位置、レビューは反応、決めるのは執筆側。** 品質の点数はどこでも作らない。
6. **改稿は必ず前版と比較され、負けたら戻す。** 改稿は単調増加しない。

優先順位（衝突時）: 投稿先・応募先の規定 ＞ ユーザーの明示指示 ＞ 作品の文体仕様書・ジャンル契約 ＞ 既存原稿の声 ＞ プロファイル既定値 ＞ 汎用既定値。21 §0.2、22 §13、03 冒頭、ANA の 6 段裁定はこの順で矛盾なく重なる。

**対になる失敗（原則 3 の実体）**

| 締める対象 | 横滑り先 | 同時に数えるもの | 出典 |
|---|---|---|---|
| 感情の名指し | 身体反応テンプレの爆発 | emotion_* と body_template の合算 | 23 L5-2、22 §11-2、09 |
| NG 語 | 近縁語（ふと→不意に、静かに→ひっそりと） | 対象語＋近縁語群の密度 | 23 §10.1、21 §0.4、24 C5、08 |
| 「……」「――」 | 「沈黙が落ちた」型の抽象擬人化、電報体 | kigo 頻度と L1-7、短い一文段落の連続 | 23 L1-7、short-deslop §7 |
| 章末の総括 | 予告ナレーション型のフック | 段落末ボタン文と cliffhanger パターン | 23 L3-2 / L8-4、22 §3.4 |
| 装飾タグ | 全台詞への動作ビート | タグ密度とビート密度 | 21 §12.5、23 L4-6 |
| 視覚偏重 | 感覚の均等盛り・後付けの匂い | 視覚のみ場面率と、感覚文の直列配置 | 23 L3-5、21 §0.4、06 §5 |
| 文末「た」連続 | 機械的な交互配置 | 連続長と、出来事文のル形率 | 21 §1.2 悪例 B |
| 冗長 | 電報体・白描への過剰適応 | 削除率と文長 CV、一文段落率 | 11 規則 7、01 §2.8 |

### 2.1 論点 1: NG 語リストを執筆時に見せるか

**各ソースの立場（事実）**

| ソース | 規則 |
|---|---|
| 23 §10.1〜10.4 | 執筆時は失敗カタログ・NG 語・lint 閾値を読ませない。語リストは scripts/data の JSON に置きスクリプトだけが読む。LLM に渡るのはヒット行と前後のみ。推敲時もヒットした層の処方だけ。語の置換は禁止し文単位で再設計。執筆時ハード規則は 5〜7 個。例外はユーザーが明示した 5 語以内の個人リスト。名前の頻出リストも LLM に読ませない |
| 24 A2 / C5 | SKILL.md 本体に NG 語本体を置かない。予算語（ふと 1、思わず 1、どこか 2 等の章あたり上限）は執筆前に見せず初稿後の点検で使う。理由は同義語への癖の移動 |
| 03（原資料 §5） | 常時ロードの本文に禁止表現を持つ。ただし極小: 強調語 4 つ、締め癖の文末 2 つ、原理 2 つ（説明を比喩に逃がさない／行為者を主語に）。測れるものは lint へ、と自ら分業を宣言 |
| 01 | description にまで NG 語例（運ぶ・効く・開かれた問い）を入れ、トリガー精度と予告を兼ねる。本文 24KB を常時ロード。ただし中核は語ではなく「生成機構の 3 経路＋2 段階判定」と「これは違反ではない」の安全弁 |
| 21 §0.3 / §16 / §19 | 執筆前に読む文体仕様書に作品別の「禁止語・偏愛語」欄。一方、汎用の悪癖辞書は scripts と推敲パス用で、「初稿は声を優先し、規則は推敲で使う」 |
| ANA（07 / 08 / 11） | 三層防御（プロンプト注入→writer 自検→独立 anti-ai）。writer のブリーフに T1 簡表と題材別疲労語 5 つ、未蒸留時は「AI が犯しやすい誤り」欄を注入。ただし生成と清創は分離し T2 / T3（集積・密度系）は入れない。読み込み順は「正の方法論→禁止表」。禁じるのは語でなく修辞動作 |
| 05 / 06 | 世界制約（存在しない語彙／概念／人物の知識外）は執筆パックに入れ、「事後修正でなく最初から使わない」 |
| 02 | 規範の語彙・例文は出力へ漏れる。だから漏出テスト（スキル内語彙で原稿を検索）を点検に組み込む |

**食い違いの正体**

「禁止語」という一語に性質の違う 4 種が混ざっている。分ければ対立の大半は消える。

| 種別 | 例 | 誘発リスク | 代替の一意性 |
|---|---|---|---|
| A 世界制約語 | 時代物のスマホ、異世界のメートル | 低（文脈上の事前確率が低く、載せても引き寄せにくい） | 高（機能等価表現に翻訳できる） |
| B 作品契約語 | ユーザーが「この語は使わない」と決めた語、語り手の偏愛語 | 低〜中（短ければ抑止が勝つ、という点で 23 と 03 は同じ理屈） | 中 |
| C 汎用の癖語と閾値 | ふと、静かに、息を呑む、1,000 字 3 回 | 高（最頻値そのもの。載せると確率が上がり、抑えても近縁語へ移る） | 低（置換先も紋切り） |
| D 修辞動作 | 否定対比、場面末の総括、三点列挙 | 例文を載せると高い | 操作として言い直せる |

**裁定表**

| フェーズ | 文芸 | エンタメ | Web 連載 | 短編 |
|---|---|---|---|---|
| 企画 | 文体仕様書に「使わない語≤5／偏愛語≤5」。記入はユーザー発のものだけで、スキル側から候補を提案しない。A は別表（件数制限なし、可能なら「現代語→作中語」の対応表で持つ） | ＝ | ＝＋「この作品で再発した型」欄を空で用意 | flash は仕様書なし。2,000 字超は左に準ずる |
| 執筆 | 渡す: 作品メモ、声シート、場面カード、直前 1,000〜1,500 字、別題材の手本段落、A、B（≤5）。渡さない: C の全部、D の例文、過去の lint 結果。D は肯定形の操作 3〜5 個に翻訳して渡す | ＝ | ＝＋作者承認済みの回帰型を最大 5 件、「型＋代わりにやる操作」の形で。長文生成はバッチごとに硬規則欄を再注入 | ＝（flash はブリーフ 1 枚のみ） |
| 機械検査 | 辞書 JSON はスクリプトだけが読む。出力はカテゴリ ID・行・前後 30 字・密度と閾値。総合スコアなし。作品別辞書で偏愛語とライトモチーフを除外 | ＝ | ＝＋回帰原文の完全一致は FAIL | ＝ |
| 推敲 | 直さないケース集を先に通す→ヒットしたカテゴリの処方ファイルだけ読む→置換でなく文の再設計→各ヒットに fix / keep（keep は 1 行理由。keep が 3〜5 割で正常、全部 fix は失敗扱い） | ＝ | ＝ | ＝（flash は自己点検 1 回） |
| レビュー | 読者役は本文のみ。編集役は意図（ビート）と文体仕様書まで。カタログはどの役にも渡さない。校閲役にだけ表記 lint の出力を渡す | ＝ | ＝ | 読者 1＋編集 1 |

D を肯定形に翻訳する例（執筆ブリーフの書式）:
- 場面は行為・台詞・像のどれかで切る。切ったあとに意味づけの文を足さない。
- 判断は正面から一度だけ述べ、根拠を隣に置く。
- 感情が動いたら、その人物がいま手にしている物への行為を書く。
- 起きていることは喩えを介さず書き、喩えは視点人物の生活圏から 1 場面 1〜2 個。

description（常時システムプロンプトに載る）には NG 語の実例を入れない。代わりに症状名（文末単調、説明過多、場面の要約化）と日本語のトリガー語を入れる。

**根拠**
- description と SKILL.md 先頭は執筆時にも文脈に居続ける（24 の確認事項）。ここに C を置くと「執筆時に見せない」が構造的に破れる。
- 誘発と横滑りは 23・21・24・08 の 4 本が独立に報告し、02 は漏出を点検工程に組み込むほど常態と見ている。ANA 自身も T2 / T3 を入れず「正の方法論が先」としており、全面注入派ではない。
- A と B は性質が違う。05 / 06 が「否定形の具体語リストのほうが遵守率が高い」と評価したのは A であり、C の話ではない。23 の 5 語例外と 21 の仕様書欄は B で一致する。
- 03 の常時ロード部は「語」と「原理」に分解できる。原理（直接の言葉で書く、行為者を主語に）は肯定形の操作なので執筆時に残し、語は辞書へ移せば、03 の最小主義と 23 の分離は両立する。

**採らなかった側の言い分**
- ANA: 最初の層で減らせば後工程の改稿量が減り、改稿による劣化（23 L8-6）も減る。→ もっともなので、Web 連載に限り「その作品で実際に再発し作者が承認した型」5 件までを執筆時に認めた（汎用カタログの転記は不可）。
- 03: 4 語程度の常時提示なら抑止が勝つ。→ 23 の 5 語例外と同じ理屈で否定しきれない。A/B-1c で確かめる。
- 01: description の NG 語例は起動精度を上げる。→ 症状名とトリガー語で代替し、起動率を A/B-1e で比べる。

**A/B で確かめる点**
- 1a: カタログ同梱版と手順誘導版で、対象語の 1,000 字密度と近縁語群の密度を両方測る。盲検読者のペア比較勝率も取る。
- 1b: 2,000 字と 8,000 字で、後半 1/4 の密度を比べる（否定指示の減衰）。
- 1c: 執筆時の提示語数 0 / 5 / 15 / 40 で、対象語密度・横滑り・勝率の曲線を取り、5 語上限の妥当性を見る。汎用 4 語の常時提示（03 方式）もこの系列に入れる。
- 1d: 時代物・異世界で世界制約表を渡す／渡さないの現代語混入件数（A は渡したほうがよい、の確認）。
- 1e: description に NG 語例あり／症状名のみ、での起動率と誤起動率。
- 1f: 渡したもの全部（禁止語、手本段落の句、操作指示の語彙）を漏出検査リストに入れ、漏出率を常時監視する。

### 2.2 論点 2: 五感 — ノルマか、選択か

**各ソースの立場（事実）**

| ソース | 規則 |

4. 一つの感情は一度。あとから痛みの説明を足さない。
5. 台詞内の感情語は対象外。
6. 置換した結果が別の紋切り型なら、元のほうがまし（keep）。

- ANA anti-ai の定級: 重い原稿に軽い介入では足りない。→ 採用。ただし LLM の判定ではなく機械の計数から出す。

**外部モデルへの持ち出し**: 別系統のモデルに見せる運用は 23・24・05 / 06 が揃って価値を認める（癖の分布が違い、互いの最頻値が目立つ）。その場合も盲検条件、点数と修正文を採らない規則、同じ重大度基準での裁定を維持する。持ち出し用の依頼文テンプレと、返答を指摘フォーマットへ正規化する手順を references に用意しておくとよい。

**A/B で確かめる点**
- 4a: 点数つきレビューと順位＋引用レビューで、指摘の引用率、改稿後の盲検勝率。
- 4b: 修正文ありと方向のみで、改稿後の body_template・癖語の密度変化（再注入仮説）と話者当て正答率（声の混入）。
- 4c: 強度を点数で取る場合と順位で取る場合の、企画曲線からのずれの検出力。
- 4d: 「問題を最低 3 つ」の強制が無理な指摘を生む率（執筆側の keep 率で測る）。

### 2.5 論点 5: 章末フック必須と、余韻・開いた結び

**各ソースの立場（事実）**

| ソース | 規則 |

| ANA（11 §2.12、10 §2.4） | 全衝突が章内で完全に解決する「安全着陸」は不合格。感情の最高点は章末の 1/4 手前あたり、章末はフック。章末 13 式・章頭 7 式、連続 2 章で同型を使わない、日常章に強フックは不要、最終章は収束。偽の懸念と、章末の危機を次章頭の偶然で解く手は禁忌 |

**切替条件**: `medium`（分割配信か一括か）と `chapter_hook`（required / optional / off）。分割配信で話と話のあいだに日が空く媒体だけ required。章ビートの `ending_type` で個別に上書きでき、上書きには 1 行の理由を書く。

**裁定表**

| フェーズ | 文芸 | エンタメ | Web 連載 | 短編 |
|---|---|---|---|---|
| 企画 | `chapter_hook: off`。結末案を 3 つ出して選ぶ | `optional`。作品全体で開いた問いが常時 1 本以上あるよう構成 | `required`。各話の ending_type を 7 種（問い／反転／決断／危機／期限／約束／余韻）から選び、直近 2 話と同型にしない。余韻型は喪失回・アークの締め・最終話に使え、連続は不可 | 作品末のみ設計。通俗型で章立てがあれば Web 連載に準ずる |

長編の文芸でも「開いた緊張が 1 本もない区間」は INFO として報告する（02）。FAIL にはしない。円環は選択肢の一つとし、同じ作者の複数作で毎回なら作品間反復として警報。

- 5b: 文芸短編でフック型／開いた結び／総括結びを下読み役に強制順位づけさせる。
- 5c: フック必須を文芸に適用したとき、予告ナレーションのパターン発生率が上がるか。
- 5d: 同型禁止の窓が 2 話と 3 話でどう変わるか。

### 2.6 論点 6: 会話タグ — 「言う系 8 割・副詞禁止」と日本語のタグ省略

**各ソースの立場（事実）**

| ソース | 規則 |
|---|---|
| ANA（11 §2.4、07、08、09） | タグは言う／訊く系の素朴な動詞が 8 割以上、タグへの副詞修飾は禁止し動作で代替。同一タグの 3 連続なし。地の文なしの台詞連続は 8 まで（密集段 12）。台詞 1〜2 句ごとに微動作を 1 つ、動作が先で台詞が後、動作と台詞の感情は反差させる。第 2 パスの検証値は台詞タグ密度 10% 未満。一問一答のピンポン連鎖が AI 信号。「と言った」級の基本タグは叙述の基盤なので直さない |

**食い違いの正体**

ANA の 8 割は分母が曖昧で、全台詞を分母にとれば日本語では「と言った」の連打になる。タグを付けた台詞を分母にとれば、21 の「装飾タグを避け素のタグを使う」と同じ主張になる。また ANA の「1〜2 句ごとに動作」は、21・23 が LLM の癖として名指しする全台詞ビートそのもので、こちらは真の衝突。

**裁定（共通）**
1. 話者表示の優先順: 省略（口調と文脈で分かる）＞素のタグ（言った・訊いた・答えた）＞場面固有の物を使うビート＞装飾タグ。
2. 8 割規則は「付けたタグのうち素の動詞が 8 割以上」と読み替えて採用。様態の副詞つきタグは 1 話 1 回まで。
3. ビートは台詞 3 つに 1 回が目安、転機に寄せる。ANA の「1〜2 句ごと」は不採用。「動作が先・台詞が後」「動作と台詞の感情を反差させる」は、ビートを置くと決めた箇所の作法として採用。
4. ピンポン連鎖の対策はビートの挿入ではなく応答設計で行う（3 回に 1 回は答えない・ずらす・聞き返す・遮る）。
5. 話者識別は声で。話者当て 70% 以上、かつ語尾を正規化した版でも当たること。
6. 同一話者のかぎ括弧を連続させない。3 人以上は 2 往復に一度、話者を指す。

**裁定表**

| フェーズ | 文芸 | エンタメ | Web 連載 | 短編 |
|---|---|---|---|---|
| 企画 | 声シート（文の長さ、語彙の出どころ、言わないこと、質問への応じ方、癖 1 つ）。役割語は使わない。時代物等は契約で許可。呼称表と敬語段階を仕様書に | 役割語キャラは 2 人まで | ＝ | 2 人きりの掌編は声シート省略可 |
| 執筆 | 上の優先順で書く。重要な場面ほど本題を言わせない | ＝ | ＝。掲示板回・配信コメント回など様式のある回は契約で別扱い | ＝ |
| 機械検査 | 2 人会話のタグ・ビートなし連続: 6 発話で INFO、8 で WARN。装飾タグ・定型ビート 1,000 字 4 回。全台詞ビートの検出。6 字以下台詞 15% 未満／60 字以上 20% 超／完全文率 70% 超 | 8 で WARN | 10 で WARN（話者当て 70% 以上が条件） | 文芸型 6、通俗型 8 |
| 推敲 | 読者役が取り違えた箇所にだけ話者の手がかりを足す。足すのは素のタグか固有のビート。装飾タグへは逃がさない | ＝ | ＝ | ＝ |
| レビュー | 話者当て（台詞だけ、話者名を伏せる）。語尾マスク版も。長編は 5 章に 1 回程度 | ＝ | ＝ | 短編は 3 人以上の会話がある場合のみ |

**根拠**
- 日本語は一人称・文末・敬語・授受表現で話者を示せる。タグは最後の手段で足りる（21 §7 / §12、22 §4.2）。
- ANA の boundary が「と言った級は直さない」としている以上、ANA の本意は装飾の抑制であり、タグの増量ではない。
- 全台詞ビートは 21・22・23 の 3 者が LLM の癖として挙げる。ANA 式を日本語に機械適用すると「〜と言って頷いた」の量産になる（09 の指摘）。

**採らなかった側の言い分**
- ANA: 裸の台詞の連鎖は機械的に見える。動作を前置した帰属に換えるべき。→ 原因は帰属の欠如でなく応答が論理的すぎることにある、と見て応答設計側で対処した。取り違えが実際に起きた箇所には手がかりを足す。

**A/B で確かめる点**
- 6a: ANA 式（全台詞基準で言う系 8 割）と日本語式（省略優先）で、盲検読者の話者取り違え数と「くどい」指摘数。

### 2.7 論点 7: 「……」「――」

**各ソースの立場（事実）**

| ソース | 規則 |
|---|---|
| short-deslop 原資料 §8 | 本文に省略記号とダッシュを一切出さない。間・嗚咽・中断は短文・句点・動作・改行で。機械置換でなく意味レベルで書き直す（動機は中国プラットフォームの事情） |
| ANA 長編（08 §2.2 / §2.6） | ダッシュは数でなく用法で判定。削って意味がぼやけないなら削る。同段 3 箇所以上は診断シグナル。台詞の遮断、声の引き伸ばし、内心の言いよどみは保持 |
| 21 §12.5 / §16 / §18 | 2 字分 1 単位。1,000 字に各 3〜4 回を超えたら警報。「……」だけの台詞は 1 場面 1 回。言い淀みは 1 発話に 1 つ、淀む人物と淀まない人物を分ける |

**裁定**

全面禁止はどのプロファイルでも採らない。日本語では 2 倍角・偶数個が正書法で、禁止は不自然な句点と電報体、そして「沈黙が落ちた」型への横滑りを生む。置くのは表記の正しさ（FAIL）と頻度上限（WARN）、用法の削除テスト（推敲）の 3 つ。

| フェーズ | 文芸 | エンタメ | Web 連載 | 短編 |
|---|---|---|---|---|
| 企画 | 表記プロファイル print。ダッシュの字形を統一。口癖として使う人物は声シートで宣言 | ＝ | web。単独「…」を流儀にする作者は契約で無効化 | 投稿先に合わせる |
| 執筆 | 2 倍角偶数個。沈黙はまず台詞のあいだの即物的な 1 文で作る | ＝ | ＝ | ＝ |
| 機械検査 | 単独・奇数は FAIL（自動修正可、作中のチャット文面等は除外マーカー）。各 1,000 字 3 回で WARN。「……」始まり台詞 15% 超、「……」のみ台詞 1 場面 2 回で WARN | 4 回 | 6 回 | 文芸型 3、通俗型 4 |
| 推敲 | 削除テスト（記号と両側を削って意味がぼやけるか）。残す＝台詞の遮断、言いさし、内心の言いよどみ、因果や状態を補う間。削る＝同格説明の挿入、沈黙の代用。WARN が出ても記号だけを句点に置換しない | ＝ | ＝ | ＝ |
| レビュー | 特に問わない | ＝ | ＝ | ＝ |

**根拠**: 21・22・23・24 の 4 本が偶数個を正書法として扱い、10 と 08 のレポートも全面禁止を日本語に不適と判定している。ANA 長編の削除テストは日本語の「――」にそのまま使える。short-deslop から採るのは「機械置換でなく意味レベルで書き直す」という執行方法と、記号に頼りすぎないという精神だけ。

**採らなかった側の言い分**: short-deslop は、記号を封じれば間を動作と改行で作らざるをえず文章が具体的になる、と考える。→ 第一手段を文の切り方に置き、記号に予算を与えることで同じ圧力をかけた。

**A/B で確かめる点**
- 7a: 全面禁止版と頻度上限版で、日本語読者役の「不自然な句点・電報体」指摘数と、抽象擬人化（沈黙が落ちた等）の密度。
- 7b: 閾値 3 / 4 / 6 をプロの商業作品コーパスで較正する。
- 7c: 自動修正が意図的な破格を壊す率。

### 2.8 論点 8: 改稿方式の統合

|---|---|
| 23 §10.5 | 下書きは止まらず最後まで→機械検査→診断のみ（構造→場面→文→表記の順に固定、修正文はまだ書かない）→保護リスト（最も良い文を 3 つ固定）→差分改稿（全文再生成は場面自体の差し替え時のみ）→再検査と盲検 A/B→最大 3 周。A/B で勝てなければ前版に戻す。2 周目以降は削る改稿を優先。各ヒットは fix / keep |
| 24 C4 | 上限は flash 1／short 2／連載通常章 2／第 1 話・山場・最終章 3。打ち切り 5 条件（S1=0 かつ S2≤1／新規指摘が S3 以下／同一箇所の往復／盲検 A/B で勝てない／上限到達）。改稿指示書に守る長所を明記 |
| ANA anti-ai（07） | 全文最大 3 ラウンド。同じ段が 2 ラウンド連続で無変更ならスキップ。3 ラウンド後も 10 箇所以上残れば要再確認の印を付けて先へ。削除量の上限は軽 15／中 25／重 35%。直す前に免除判定（SKIP を記録）。草稿は上書きせず別名。筋は変えない |
| ANA 段落種別（08 §2.3） | 叙事段＝大幅可、会話段＝タグとリズムだけ（台詞原文・数字・発言者を保護）、内心段＝文型のみ、回想段＝事実の骨格を保つ、作中文書＝不改 |

| ANA 同源検収（07） | 生成に使ったブリーフで逐条照合し、FAIL なら違反報告つきで再執筆。3 回で打ち切り、違反最少の稿（同点は最新）を採る |

| 02 | 推敲で新しく書いた文は、書いた直後に再テスト |

**食い違いの正体**

周回上限 3 は全員一致。違いは (1) 1 周で触る範囲（窓 1 つか、指摘全部か）、(2) 差分改稿かリロールか、(3) 止める条件、(4) 削る量。いずれも排他的ではなく、1 本の手順に直列化できる。

**統合手順（共通）**

1. **版の保全**: 草稿は上書きしない（別名保存か節目のコミット）。
2. **保護の宣言**: 保護文 3 つ（選ぶのは読者役の「読み返した行」を優先し、無ければ執筆側）＋作者のロック台詞＋段落種別の保護項（台詞原文・数字・人名・時系列・作中文書）。
3. **診断**: 視点→構造→場面→文→表記の順。修正文は書かない。直さないケース集を先に通す。
4. **範囲の宣言**: 1 周で触るのは最大 5 箇所。宣言外は文字単位で不動。
5. **差分改稿**: 削除＞書換＞再生成の順に試す。置換でなく文の再設計。新しく書いた文は直後に再テスト。
6. **機械照合**: 保護文が残っているか、変更行が宣言範囲内か、増減が上限内か（1 周の削除は 15% まで、累積 35% まで、増加は 5% まで。字数規定は割らない）。
7. **再照合**: 状態宣言（時刻・場所・持ち物・知識）と未決事項に対して。
8. **盲検 A/B**: 新版が選ばれなければ前版を採って終了。
9. **停止条件**（いずれか）: (a) A/B で勝てない (b) S1=0 かつ S2≤1 (c) 同じ段落が 2 周続けて無変更なら以後スキップ (d) 同一箇所の往復 (e) 同種の直しを 2 周して改善なしなら 3 周目は同種を禁じ、構造に戻るか巻き戻す (f) 上限到達→残件は backlog へ。

**リロールとの分岐**: 契約違反（視点の破綻、must_not 違反、ビートが要約で済まされている）が場面の過半に及ぶときだけ、場面単位でリロールする。最大 2 回、計 3 稿から違反最少（同点は盲検 A/B）で採る。それ以外は差分改稿。リロール時は保護文を引き継がない（場面ごと差し替えるため）が、旧稿は残す。

**裁定表**

| フェーズ | 文芸 | エンタメ | Web 連載 | 短編 |
|---|---|---|---|---|
| 企画 | 契約に `max_rounds: 2`（山場 3）、保護文 3〜5 | 2（山場 3）、保護文 3 | 2（第 1 話・山場・最終話 3）、保護文 3＋決め台詞のロック | 2（flash 1）、保護文 3 |
| 執筆 | 途中で推敲しない。場面単位で保存 | ＝ | ＝ | ＝ |
| 機械検査 | 保護文照合、差分範囲照合、増減率 | ＝ | ＝＋回帰原文の照合 | ＝ |
| 推敲 | 各周の最後に「語り手の声として自然か」を確認し、損なう修正は戻す。2 周目以降は削る優先 | 標準手順 | 時間制約が強い。通常話は S1 と S2 上位だけ直して先へ | 触るのは最弱の場面 1 つに集中（ANA の窓 1 つ方式に近い運用） |
| レビュー | 盲検 A/B を各周で | ＝ | 第 1 話・山場のみ毎周。通常話は最終版と初稿の 1 回 | 最終版と初稿の 1 回 |

**根拠**
- 23 と 24 は、LLM の改稿が無難化・平板化へ向かうことを前提に、比較と保護を置いている。ANA の誤殺防護・削除量上限・段落種別の保護も同じ危険への別の歯止めで、重ねて矛盾しない。
- 「窓 1 つ」は検出器スコアの因果を切り分けるための規律で、読者反応が目的の改稿には厳しすぎる（3 周で 3 箇所しか直せない）。一方「宣言外は不動」をハッシュで検証する発想は、03 の「直した隣を壊す」事故に直接効くので、範囲を 5 箇所に広げて採用した。
- 「同種の直しを 3 周続けない」は、語の入替を繰り返して紋切りが巡回する現象への対策として、検出器文脈から切り離しても成立する（08 のレポートも同判断）。
- リロールは ANA の同源検収が示すとおり、違反が構造的なときは差分より速く、最少違反稿の選択が劣化を抑える。ただし文体レベルの問題に使うと良い破調まで失うので、契約違反に限定した。

**採らなかった側の言い分**
- ANA structural-heat: 触る箇所が多いと、何が効いたか分からなくなる。→ 周ごとに A/B を取ることで周単位の因果は追える。箇所単位の因果が要るのは較正実験のときだけ。
- 21: 観点ごとに別パスで 9 回読む。→ 観点の順序は採用。パス数は周回上限と両立しないので、1 周の診断の中で順に見る形にした。
- 23: 保護文は 3 つ。→ 文芸だけ 5 まで許した。声が商品のため。

**A/B で確かめる点**
- 8a: 全文再生成の改稿と差分改稿で、盲検勝率、保護文の残存率、文長 CV と段落長 CV の変化（均される仮説）。
- 8b: 1 周で触る箇所数 1 / 5 / 無制限。
- 8c: 周回数 1 / 2 / 3 / 5 の勝率推移（単調に上がらないことの確認と、最適な上限）。
- 8d: 停止条件 (c)(e) の有無で無駄な周回がどれだけ減るか。
- 8e: 保護文を選ぶ主体（執筆側／読者役の読み返し行）の違い。
- 8f: 削除上限 15% の妥当性（10 / 15 / 25）。

### 3.3 scripts に持たせる契約

- **辞書の置き場**: `scripts/data/*.json`。汎用辞書と作品別辞書（偏愛語・ライトモチーフ・口癖の除外、回帰原文、ロック台詞）。LLM が Read する導線を SKILL.md に書かない。
- **lint の出力**: カテゴリ ID、行、前後 30 字、密度と閾値。40 行以内の要約。総合スコアなし。FAIL は機械的に誤りと断定できるものだけ（約物の表記、用語表の禁止表記、回帰原文、字数規定）。
- **対の同時表示**: 1.3 の対表に従い、片方の警報に相方の値を必ず併記する（例: 名指し 5 回／テンプレ 1 回）。
- **leak_check**: 執筆時に渡したもの全部（禁止語、手本段落の 8 字以上の連なり、操作指示の語彙、技法名）を検索リスト化して原稿を照合。
- **protect_check**: 保護文・ロック台詞の存在を改稿後に文字列一致で確認。
- **diff_scope_check**: 変更行が宣言範囲内か、増減率が上限内か。
- **endings_log**: 章頭・章末の型を記録し同型連続を警告。
- **speaker_mask**: 台詞だけを抜き、話者名を伏せた版と語尾を正規化した版を出力。
- **triage**: カテゴリ別ヒット分布から介入の深さ（軽／中／重）を決定的に出す。表示先は親だけ。

### 3.5 A/B ハーネス（論点横断）

同一ブリーフ×条件ごとに 10 本以上を生成し、(1) 機械指標（対象と横滑り先の両方）、(2) 盲検ペア比較（順序ランダム、できれば別系統モデルを判定役に）、(3) 再話と企画の一致、(4) 話者当て、(5) 執筆側の keep 率、を取る。判定役が同系モデルのときは、その旨を結果に明記し、ユーザーの目視抜き取りを併用する。プロの商業作品と素の LLM 出力の双方で lint を走らせて閾値を較正する作業は、23・21・24 が共通して未実施としている最大の宿題。

## 4. 特に優れている点 TOP 10（衝突を解く鍵になった知見と、LLM に効く理由）

1. **癖は語でなく分布であり、語を見せると誘発し、抑えると横滑りする**（23・21・24・08、傍証として 02 の漏出）。LLM は文脈内の語の確率を上げる。否定指示は長い生成の後半で弱まる。だから見せる／見せないの線引きが品質に直結する。
2. **名指しと身体テンプレを同時に数える**（23 L5-2、22）。一方だけ締めると他方が増えるという、規則の副作用まで規則にしている。1.3 の対表はこの一般化。
3. **「その文は主人公の今の主観感情を帯びているか」の一問**（short-deslop）。ジャンルで規則が反転する領域で、LLM が自己判定できる単一基準を与える。
4. **後続が新情報か言い換えかで二度書きを判定する**（03 の駄文テストを 21 と short-deslop の橋に使う）。文芸と通俗の衝突を、削るか残すかの選択だけに縮約できる。
5. **点数禁止・修正文禁止・「AI っぽいか」を聞かない**（23・24・ANA reader）。採点表を渡すと LLM は全項目に無難な所見を並べ、修正文を書かせるとレビュアーの癖が原稿に入る。順位と引用は甘さを構造的に封じる。
6. **盲検 A/B で負けたら戻す**（23・24）。改稿が単調に良くならないという LLM 固有の性質への、唯一の直接的な歯止め。
7. **誤殺防護と段落種別の保護**（ANA boundary）。推敲の過剰修正で口癖・数字・台詞が潰れる事故を、直す前のゲートで防ぐ。
8. **余韻を引きの型の一つに数える**（22）。フック必須と開いた結びの対立を、型の選択と連続禁止の問題に変える。
9. **ANA の 8 割規則の分母を読み替える**。付けたタグのうち素の動詞が 8 割、と読めば日本語のタグ省略と矛盾せず、装飾タグの抑制という本意だけが残る。
10. **宣言外は文字単位で不動、をハッシュで検証する**（ANA structural-heat）。検出器対策という出自を外せば、「直した隣を壊す」（03）への機械的な対策になる。

次点: 材料がなければ平坦なまま残す（02）。等級はルーティング専用にして品質指標にしない。回帰型≤5 を執筆時の例外にする（作者の実際の赤入れだけが執筆時に見せる価値のある否定情報）。

## 5. 弱点・欠落・未解決

- **根拠の大半が経験則**。誘発と横滑りは 4 本が一致して報告するが、日本語小説での定量検証はどのソースにもない。本裁定の論点 1 は A/B-1a〜1c の結果で覆りうる。
- **プロファイルの境界が曖昧**。ライト文芸、キャラ文芸、文芸寄りの Web 作品は複数にまたがる。既定値を引いた上でキーごとに上書きする運用を前提とするが、初期化時の質問が増える危険がある（質問は媒体・規模・描写上限の 3 問までに抑えたい）。
- **通俗型短編の設定値は原資料が中国語の有料短編市場に依拠**。日本の「ざまぁ」「スカッと」系で同じ読者契約が成り立つかは未確認。ジャンル読者役の設計が弱いと、文芸の基準で裁いてしまう。
- **ジャンル読者役の品質**。LLM にジャンルの約束事を演じさせる指示書がまだ無い。22 §6 が素材になるが、役割ファイルとしては未作成。
- **二度書き判定を LLM が安定して下せるか不明**（A/B-3d）。
- **盲検 A/B のコスト**。各周で別コンテキストを 1〜2 本起動する。flash と連載通常話では重い。頻度を落とした運用（最終版と初稿の 1 回）を裁定に入れたが、劣化の見逃しは増える。
- **同系モデルの判定バイアス**。A/B 判定役が執筆役と同系だと、同じ癖を自然と感じて新版（より整った版）を選びやすい可能性がある。別系統モデルかユーザー目視の併用が要る。
- **触れなかった衝突**: 段落頭の字下げ（06 は原稿で入れない、21・22 は入れる）、一人称の既定、文長の既定帯（03 の 40〜70 字と 21 の平均 35〜45 字）、視点の予告文の扱いなどは本追加調査の範囲外。字下げは「原稿は字下げなしで持ち、エクスポート時に付与」（06 の改変案）と「原稿側で入れる」（22）が割れたままなので、別途裁定が要る。
- **ANA の SOP 本体（skills 配下）は 07 の時点で未読部分がある**。Gate や 6 量化指標の内訳は 11 が補ったが、定級の算式は確認できていない。

## 6. 新スキルへの取り込み提案

### そのまま採用（考え方として。文言は書き下ろす）
- 執筆時に渡すものと渡さないものの表（3.2）と、辞書を scripts/data に隔離する構成。
- ユーザー指定の禁止語 5 語以内の例外、偏愛語の作品別除外。
- 世界制約 3 区分の執筆時提供と、機能等価表での持ち方。
- 名指しとテンプレの同時カウント、4 択置換、通過点は語り山場は見せる、置換先が紋切りなら keep。
- レビュー役の出力契約（点数なし、文面なし、引用必須、最弱箇所の強制指名、再話）と盲検 A/B。
- 改稿指示書（5 項目、方向のみ、守る長所 2〜3 点）。
- 引き 7 種（余韻を含む）と同型連続の禁止、危機は次話冒頭 300 字以内で受ける。
- 約物は偶数個が FAIL 判定、頻度は WARN、用法は削除テスト。
- 改稿の統合手順 9 段と停止条件 6 つ、段落種別の保護項、削除＞書換＞再生成。

### 改変して採用
- 五感: 下限ノルマと事後追記を廃し、関心の錨＋上限＋視覚のみ診断へ。場面タイプ別表は警報後の参照物に。
- ANA の T1 簡表注入: 汎用表の注入はやめ、作者承認済みの回帰型 5 件までを Web 連載で許可。
- ANA の「AI が犯しやすい誤り」欄: 汎用カタログからの転記を禁じ、その作品で実際に起きた誤りに限定。
- 03 の常時ロード禁止表現: 語は辞書へ、原理は肯定形の操作として執筆ブリーフへ。
- 01 の description の NG 語例: 症状名とトリガー語に置換。
- 感情強度の採点: 順位づけと引用に置換。
- 軽／中／重の定級: スクリプト算出に限定し、用途は介入の深さの選択だけ。
- 「言う系 8 割」: 分母をタグ付き台詞に。タグなし連続の WARN 値をプロファイル別に。
- 「安全着陸は不合格」: Web 連載の通常話に限定。
- 「最高スコアの窓 1 つ」: 宣言した最大 5 箇所以外は不動、に拡張。短編は最弱場面 1 つ。
- 同源検収のリロール: 契約違反が過半の場面に限定、計 3 稿から最少違反を採用。
- short-deslop の留・削対照表: 通俗型短編の設定値として採用し、全称命題（短編は余白で勝負しない）は捨てる。

### 捨てる
- 非視覚 2 つ以上の一律ノルマと「数えて 1〜2 行足す」手順。
- 台詞 1〜2 句ごとの動作ビート。
- 「……」「――」の全面禁止。
- 五次元 0〜100 採点、レビュアーへの修正文の必須化、読者役への「AI っぽいか」の質問。
- 感情表現の固定序列（動作＞台詞＞身体反応＞直述）を全作品の既定にすること。
- 感情→身体の対応表・動作庫を執筆時に読ませること。
- 外部検出器スコアに由来する数値（改善 0.05、等長改稿、行内の水増し）。

### 新規に作る必要があるもの
- ジャンル契約テンプレと既定値表（3.1）。
- 直さないケース集の日本語版（方言・役割語、一人称の饒舌、ステータス画面、意図した体言止め連打、時代物の文語調）。
- ジャンル読者の役割ファイル（ジャンル別の約束事の問い）。
- 外部モデル持ち出し用の依頼文と、返答の正規化手順。
- A/B ハーネス（3.5）と較正手順。
