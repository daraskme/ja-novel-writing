**出荷を止める問題と修正案**

1. **C01・C03：大小比較や否定を「その数に等しい」という主張として扱います。**

   次はすべて正しい文ですが、FAIL になります。

   | 再現入力 | 実測 |
   |---|---|
   | `「ありがとう」は四文字を超える。` | C01 FAIL |
   | `「ありがとう」は四文字に収まらない。` | C01 FAIL |
   | `「きゃく」は三拍に満たない。` | C03 FAIL |
   | `「ありがとう」は四文字にあらず、五文字なり。` | C01 FAIL＋C07 INFO |
   | `「きゃく」は三拍もない。` | C03 FAIL |

   [ASSERTIVE_TAIL](scripts/novel_lint.py:945) が「を・に・も・で」以降を広く受理し、[claim_context](scripts/novel_lint.py:964) が等値の主張と比較・否定を区別していません。「ありがとう」は実際に五文字なので、四文字を超えるという文を直させてはいけません。

   **修正案：** 比較・上限下限・否定・訂正・再検算を表す述語は WARN に回してください。そのうえで、格助詞以降の任意文字列を断定として受理する条件を狭め、等値の主張だと確認できない残りは WARN にします。「三文字だ」「三文字の言葉」「三文字を消した」など、既存の基本形は対照として維持します。

2. **C01：外側が『』の台詞を、人物の発言として保護できません。**

   ```text
   『「ありがとう」の四文字を言え』と弟が命じた。
   ```

   **C01 FAIL** です。人物が数え間違えている台詞として WARN にするべき例です。

   [in_open_quote](scripts/novel_lint.py:1002) は「」の個数だけを見ています。内側の引用より前にある『』を認識せず、後ろの「を言え』と弟が命じた」も断定形として通ります。

   **修正案：** C 群にも「」『』共通の括弧スタックと引用範囲を使ってください。人物の発言や分類不能な引用の内側にある数の主張は WARN にします。
