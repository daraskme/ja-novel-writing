### 告白で選ばれなかった理由（判定理由と、生成役が自分で書いた前提から）

- スキルあり版は、告白への返事を先送り・条件つき・仕草まかせにしていた。ある応答は前提に「告白は即答で受け止めさせず、返事は保留、でも会う約束は決まるという着地にしています」と自分で書いている。依頼は「直球で告白」「胸が熱くなる」「相手も気持ちを答えてほしい」だった。判定役の指摘も同じで、「交際の承諾は会う予定から読み取る部分が残る」「金属だけがまだ冷たかった、が孤独を残す」。
- スキルの側の原因は 3 つ。(1) 恋愛の場面カードの「一場面で一段だけ動かす」「縮んだら次は少し引く」は連載の途中の回の速度の決まりだが、山場の告白にも効いていた。(2)「初案を疑う」が、結末の約束（両思いの返事）にまで効いていた。(3) 場面の終わりを物や仕草で切る既定が、冷たい物・意味を読ませる仕草で温度を下げていた。
- ほかに、前提に技法の解説や「方向性が違えば直します」を足していて、判定役に「本文以外の混入」と読まれた。

### 生成役の作業記録から分かったこと（所要時間と費用）

- 最初の実行は、入れ子の Claude Code への権限の渡し方が悪く（`cd … && python`、ヒアドキュメント、全角空白で始まる `printf` が拒否された）、1 件に道具 30 回・約 11 分・約 1.1 ドルかかった。この 2 件は採用せず、権限を直して 7 対すべてを作り直した（作業ディレクトリの中にだけ下書きを置ける。生成 1 件ごとに別の作業ディレクトリ）。読み取りの不具合で出力を取りこぼした実行と、途中で止めた再試行もあり、約 2.6 ドルを無駄にした。
- 直したあとのスキルあり版は、1 件 3〜9 分・0.34〜1.06 ドル・道具 9〜41 回。スキルなし版は 20〜30 秒・約 0.04 ドル・道具なし。
- 字数の目安があると、短い初稿（目安の 6〜7 割）を書いてから数十字〜百字ずつ継ぎ足し、そのたびに `count_chars.py` で測り直していた（連載回で計測 10 回・編集 19 回）。警報線をわずかに割った数値（文長の変動係数 0.39、線は 0.40）を線の内側へ入れるための書き直しもあった。スキルは「検査は 1 回、周回しない」と書いているが、字数が足りないときの直し方が掌編の手順に無かった。

## スキルの修正（ラウンド 3 のあと）

1. `references/scene-cards.md`「告白が実る山場」を追加。返事も同じ場面で言葉にする／先送り・条件つき・仕草まかせにしない（保留や失恋は依頼か契約がそう言うときだけ）／隔てる事情は具体の約束で受ける／関係が変わったことを行為で一つ見せる／結びは二人のところで切る。

## 言えること・言えないこと

- 言える: Claude Code（Sonnet 5）が生成役のとき、直す前のスキルは、直球の告白 3 対で選ばれなかった。生成役自身が「返事は保留にした」と書いており、判定理由と一致する。直した版と直す前の版を比べた 5 対で、直す前の版が提示順によらず選ばれた対は無かった。能力バトルと連載（ラウンド 3）では、2 系列ともスキルあり版が選ばれた。
- 言えない: 勝率。直した版がスキルなしより良いこと（ラウンド 5 は割れている）。字数まわりの修正の効果。どの修正がどの選好を動かしたか。
- 判定役どうしの不一致が大きい。gpt-6-astra と Gemini が同じ結果になったのは、ラウンド 3〜5 の 17 対のうち 7 対（うち 3 対は、どちらも順序不安定）。1 つの判定役の結果を、そのまま結論にしないこと。
- 依頼は全部で 6 種。告白の依頼は、ラウンド 1 から繰り返し使っている既知の課題である。
