## 確認できた事実

### 周回を 1〜2 回で止める工夫
Claude Code 公式は、ループを「検証可能な検査が通るまで回す」と定義し、検査の締め方を四段階に分けている。同一プロンプト内の自己検査、`/goal`（別評価器が毎ターン判定）、Stop hook（スクリプトが終了を拒否）、検証サブエージェント（作業役が自分を採点しない）。Stop hook は連続 8 回ブロックで強制終了する（Claude Code Docs「Best practices」「How the agent loop works」、2026年更新）。SDK には `max_turns` / `max_budget_usd` があり、既定は無制限。実務記事は「成功条件＋失敗条件＋予算」を事前に三つ書くこと、同一フィードバックが二回続いたら停滞とみなして止めること、リトライは同じ直しを繰り返さず文脈を捨てて戦略を変えることを揃って勧める（developersdigest「Loop Engineering」、2026-07；claude.com「Loop engineering」、2026-06）。

道具の出力は「次に何字足せ」ではなく、機械可読な status と証拠に寄せるのが定石。Anthropic の Skill 指針は「スクリプトは問題を解く。Claude に丸投げしない」「エラー処理は明示的」と書く（platform.claude.com「Skill authoring best practices」、最終更新 2026-09）。チェックリストや数値検証は散文にせずスクリプトへ、というのが 2026 年の実務合意。

サブエージェントは「長いログを親文脈に入れない」「作業役と検証役を分ける」用途。公式は完了前に新鮮な文脈のサブエージェントで diff を反論させる手順を推奨する（code.claude.com/docs/en/best-practices、2026）。Codex 側も `/goal` で完了条件を別モデルが判定し、実装役に「検証が 0 なら即停止」と書かせる例がある（danielvaughan.com、2026-06）。小説の継ぎ足しそのものを公式が扱った文書は見つからなかった。

### Agent Skills の公式指針
Anthropic 工学記事（2025-10-16）と best practices（2026 更新）の骨子は次のとおり。

- 三段の progressive disclosure（name/description → SKILL.md 本文 → references/scripts）。本文は目安 500 行／約 5,000 トークン。参照は SKILL.md から一段。
- 評価から始める。スキルなしで落ちる点を見て最小の指示を足す。Haiku/Sonnet/Opus で試す。
- 自由度を脆さに合わせる。判断は高自由度（文章）、 fragile で一貫性が要る操作は低自由度（パラメータの少ないスクリプト）。
- 相互排他の文脈は別ファイルに分け、同時に読ませない。
- 品質が要る作業にはフィードバックループを入れる。ただし検査は検知器であり、モデル固有の定数を本文に固定しない、は利用者側の原則と矛盾しない。

公開実例は anthropics/skills。xlsx は `recalc.py` が JSON で誤りを返し、直して再計算する。pptx/docx は生成後に PDF/画像化して目視する「検証コマンドの固定セット」を本文に書く。skill-creator はスキルあり／なしを別サブエージェントで走らせ、プログラムで測れる断言はスクリプト、定性は grader サブエージェント、と役割を分ける（GitHub、2025-09 公開・2026 更新）。

## 推測（事実ではない）
字数ループが止まらない主因は、検査が「足りない→足せ」と修正命令になっている点だと推測する。公式の収束条件は「単調に良くなる検査」（テスト全通、diff 空）であり、創作の字数は足すほど整合が壊れるので、同じ型のゲートにすると 4〜7 周して負ける、は予想どおり。初稿 55–65%・一度に 3 割しか足さないのは Sonnet 5 の生成長バイアスで、本文に 1.3 倍と書いても効かない、とも整合する。

「駅前の告白」の判定割れは、感情の名指し不足より「告白成功が転勤後の選択に繋がるか」の山場設計だと推測する。スキル本文の「像や行為で切る・余韻」が direct 契約より強く、gpt-6-astra がスキルなしを選ぶ理由と一致する。

## 未解決問題への打ち手（3つ以内）

1. **字数ゲートをハーネス側で閉じる。** 検査スクリプトは字数を報告するだけ（不足 N 字・何を足せ、は出さない）。終了条件は「検査は初稿のあと 1 回。範囲外なら全文を一度だけ書き直すか、範囲外のまま出す。Edit の継ぎ足しは禁止」。ヘッドレスなら `max_turns` を小さくするか、2 回目の検査後は status=stop を返す。数値ノルマもモデル定数も本文に置かない。

2. **直す役を別文脈にする。** 継ぎ足しが必要なときだけ、原稿と検査結果だけを持つサブエージェントに「一回の全文書き換え」を渡し、親はパッチ履歴を持たない。公式の maker-verifier／fresh context と同じ。

3. **ジャンル契約を常時本文から外す。** 「余韻・行為で切る」と direct 告白は相互排他なので、official の「排他文脈は別ファイル」に従い、direct 時だけ `references/direct.md`（感情を発話する、成功が次の選択に繋がる、沈黙で終わらない）を読む。問題2は字数ではなく契約の上書きが原因、という読み。
