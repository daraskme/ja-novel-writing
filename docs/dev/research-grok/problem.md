## 背景

日本語小説の執筆用エージェントスキル（Claude Code の Agent Skill。SKILL.md＋references＋Python の検査スクリプト）を作っている。スキルあり／なしで同じ依頼に応えさせ、由来を伏せて読み比べる評価を 9 ラウンドやった。生成役は Claude Code（headless、Claude Sonnet 5）、判定役は gpt-6-astra・Gemini 3.1 Pro・Claude Sonnet 5。A/B を入れ替えて 2 回読ませている。

## 未解決の問題 1: 字数の指定がある依頼での「継ぎ足しの周回」

- スキルあり版の生成は、掌編 1 本（1,200〜1,500 字）に 2〜9 分・道具の呼び出し 8〜41 回・0.3〜1.1 ドルかかる。スキルなし版は 15〜35 秒・道具なし。
- 作業記録を読むと、形は毎回同じ。モデルは下書きを Write で 1 回書く → 検査スクリプト（字数と表記の lint）をかける → 字数が足りない → Edit で 100〜300 字足す → また測る、を 4〜7 回繰り返す。
- 初稿は、目安の 55〜65% で出る（「1,500 字くらい」に 800〜990 字。「1,200〜1,500 字」に 860〜880 字。指定なしで既定 3,000 字の連載回に 1,700 字）。
- 足すときも、求めた量の 3 割ほどしか足さない（「不足 486 字。600 字前後を一度にまとめて書き足す」と道具が言っても、+150〜300 字）。
- 継ぎ足しを重ねた原稿は、物の在りか・済んだ作業・時間の食い違いが増え、判定でも負けた（未到着の反物が後の段落では棚にある、など）。
- 試して効かなかったこと（いずれもスキルの本文か、検査スクリプトの出力の文言）:
  1. 「書く前に場面ごとの字数を割り振る」「直しと測り直しは 1 回にまとめる」
  2. 検査スクリプトに `--range 1200-1500` を足し、出力の最後に「次にやること: 不足 N 字。欠けているやり取りを一つ決めて一度にまとめて書き足す。測り直しは 1 度だけ」と出す
  3. 「初稿は目安の 1.3 倍のつもりで書く」
  4. 「字数を行数に直して持つ（1,500 字は約 50 行）」
- 効いたこと: 依頼に字数の指定が無い場合に限り、「既定の字数は下限ではない。届かせるための継ぎ足しはしない」で、継ぎ足しが 6 回 → 0〜2 回に減った。
- 制約: スキルの設計原則として、数値を下限ノルマにしない／一つの作風へ均さない／lint は検知器で修正命令ではない。特定のモデル（Sonnet 5）の癖に合わせた数値を、スキルの本文に固定したくない（Opus や他社モデルでも使う）。

## 未解決の問題 2: 「駅前の告白」の依頼で、判定役によって結果が割れる

依頼文: 「直球の恋愛短編の山場を一場面だけ書いて。駅前で、転勤する相手を主人公が呼び止めて『好きです。付き合ってください』と告白する。ずっと友達だった相手も、ここで自分の気持ちを答えてほしい。『うれしい』『好き』と感情をはっきり言うのが売りの話です。小道具や沈黙だけで察してもらう方向にはしないで。」

- スキルあり版は、返事を言葉にする形には直った（場面カードに「告白が実る山場」を足した）。それでも gpt-6-astra はスキルなし版を選び続け、Gemini はスキルあり版、Sonnet は順序不安定。
- gpt-6-astra の判定理由: スキルあり版は「『持つよ、改札まで』で終わるため、交際が始まった喜びや、離れる二人の今後は控えめ」。スキルなし版は「『離れてても、ちゃんと会いに行くから』と、告白の成功が転勤後の選択につながるので、恋人になれた喜びと先への希望が残る」。ただしスキルなし版には「『うれしくて、うれしくて』は感情を重ねて説明しており単調」とも書いている。
- スキルあり版は 590〜1,140 字、スキルなし版は 520〜690 字。依頼に字数の指定は無い。
- スキルの本文は、感情の名指しを禁じてはいない（ジャンル契約で direct を選べる）。しかし全体として、説明を削る・像や行為で切る・余韻を残す方向の助言が多い。
