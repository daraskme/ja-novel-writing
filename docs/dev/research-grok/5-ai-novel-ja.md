## 確認できた事実

**長さの制御。** ローカルLLM向けテンプレ（2026-08、『小説家向けローカルLLMプロンプト』）は語数を**上限**として置き、足りなければ同じ場面を水増しせず次のシーンを足せ、と明記する。Claude向け解説（AI Smiley、2026-06）も「500字以内」のように上限で縛ると薄さが減ると報告。中国語の Agent Skill「chinese-novelist-skill」（PenglongHuang、GitHub、2026-01〜）は章を3,000〜5,000字で書き、字数検査（`check_chapter_wordcount.py`）に落ちたら**継ぎ足しではなく最大3回の章ごと再執筆**。元小説家の Claude Code 実録（青羽つむぐ、note、2026-07）は本文の前に「設計書（場面目的・**字数予算**・禁止）」を人間が承認してから初稿を書く。九段理江『影の雨』（約4,000字本文に対しプロンプト約20万字）は、短い完成稿を長い指示で支える例として2026年記事でも反復引用される（matrixflow.net 2026-04 ほか）。

**「AIらしい文章」の軽減。** 2026年の日本語ガイドはほぼ共通で、(1) 禁止リストを生成前に渡す、(2) 文の長短・体言止めなど構文リズムを指定する、(3) 「嬉しい／悲しい」を動作・身体反応に戻す、(4) 参照文体を数百字貼る、(5) 書いたモデルと検査モデルを分ける。Gemini小説ガイド（aipicks、2026-06）は「感情ラベル禁止」を欠くと説明過多になると書く。これは後述の問題2と正面衝突する。

**長編の一貫性。** 公開された効き方は外付け正典である。Qiita「仕様駆動型小説開発」（pipe_render_vt、2026-03）は35話・約12万字、不変ルール＋執筆／検査／正史の3エージェント分離で「重大な設定破綻ゼロ」と報告。note「ClaudeCode用小説執筆構造」（x2775co、2026-06、配布zipあり）は world-bible・canon-log・機械検出 `check.sh`・AI臭診断スキルの3段バリデーション。Zenn「レビュー地獄」（moneymog、2026-01、続編2026-06）は全36話を後から直すと波及し、出口は「書く前の設計」と「1話→バッチと段階確認」。Zenn「学習をファイルで実装」（rads、2026-09）はセッション学習しない前提で、添削前後・差分・根拠を `CLAUDE.md` 経由で次回に読ませる。Zenn（tanuki_chan、2026-09）は「今知っていること／知らないこと」をシンボル表で渡し、知識漏洩の大半が防げるとする。

## 推測（事実ではない）

初稿が目安の55〜65%、足し分が指示の約3割、は「下限ノルマ＋lint＝修正命令」と読んだモデルが、安全側に短く書き、局所パッチで逃げる典型に見える。継ぎ足しで物の在りかが壊れるのは、青羽の「修正がパッチになり前後が壊れる」と同じ機制だと思われる。駅前告白で gpt-6-astra がスキルなしを選ぶのは、スキルの「説明を削る・像で切る」が、恋愛読者の「受諾の言葉＋二人の今後」より優先された結果、と読むのが自然。スキルなしの「うれしくて、うれしくて」単調さ指摘は、直球でも反復説明は嫌われる、という別軸。

## 未解決問題への打ち手（3つ）

1. **字数は検査の後工程にしない。** lint は字数を事実として出すだけ（「次にやること」を書かない）。字数指定がある依頼では、初稿の前に「この稿で起きるやり取りをN個」まで決め、合計がレンジに乗る設計にする。不足なら不足箇所だけを**全文書き直し1回**（chinese-novelist の章ごと再執筆）。足すな。既定字数で効いた「下限ではない・継ぎ足ししない」を、指定ありにも適用する。

2. **ジャンル契約をグローバル文体より強くする。** 「direct／感情の名指し」は許可ではなく、山場チェックリストとして references に置き、該当依頼だけで読む（wordflowlab の romance conventions 型）。例：告白の言葉 → 相手の言葉での受諾 → いま何が変わったか（転勤後の選択など）が本文にあるか。像で切ってよいのは、依頼が余韻型のときだけ。

3. **一貫性検査を「足した段落」に限定しない。** 継ぎ足しを残すなら、所持・時刻・既出事実の照合は本文全体（x2775co の機械検出、tanuki_chan の知識リスト）。ただし1を徹底すれば、この周回自体が減る。
