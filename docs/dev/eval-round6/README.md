# 評価ラウンド 6〜9（2026-09-19）

> 本評価は、限定した依頼・モデル・設定による少数試行の探索的比較です。選好は掲載した作品対に対する判定であり、一般的な勝率や品質向上を示しません。生成・判定モデルの偏り、提示順序、長さの影響が残ります。過去の評価を参考に修正した既知の課題を含むため、独立した未知の課題での検証ではありません。lint は確認候補を示すもので、文学的品質や誤りの確定を表しません。

ラウンド 3〜5（`../eval-round3/`）の続き。生成役は Claude Code（`claude -p`、Sonnet 5、Vercel AI Gateway 経由）、比較は「スキルあり（with）対 なし（base）」。判定役は gpt-6-astra（Codex CLI）、Gemini 3.1 Pro、Claude Sonnet 5（生成役と同じ系列なので、偏りがありうる）。どの判定も、同じ対を A/B を入れ替えて 2 回読ませている。前のラウンドの結果とは合算しない。

目的は 3 つ。(1) スキルの修正に使っていない依頼で比べる。(2) ラウンド 5 のあとに足した修正を確かめる。(3) スキルあり版の所要時間（掌編 1 本に 3〜9 分）を縮める。

- 連載は 3 系列ともスキルなし版。判定理由は、スキルあり版が依頼の条件（前話は作中では昨日）を「先週」と書いた違反だった。→ SKILL.md「書くときの操作」に、依頼文の固定条件を書く前に抜き出し、出す前に本文と照らす、を追加（作中の時間と、読者の側の時間を取り違えない）。

## ラウンド 8: 条件の照合を足したあとの確認（連載と日常の謎、各 2 試行）

| 依頼 | 試行 | gpt-6-astra | Gemini 3.1 Pro | Claude Sonnet 5 |
|---|---|---|---|---|
| 連載第 12 話 | 1 | base | base | 順序不安定 |
| 連載第 12 話 | 2 | base | with | with |
| 日常の謎 | 1 | with | 順序不安定 | 順序不安定 |
| 日常の謎 | 2 | with | 順序不安定 | base |

連載の条件違反は出なくなったが、別の食い違いが判定理由に挙がった（まだ届いていない反物が、後の段落では棚にある。水通しをした描写が無いのに、水通しの終わった反物になっている）。作業記録では、スキルあり版は 1,700 字の初稿を 6 回編集して 2,850 字にしていた。依頼に字数の指定は無く、SKILL.md の既定値「連載 1 話 3,000〜5,000 字」に届かせようとした継ぎ足しと読める。→ 次の 2 点を SKILL.md に追加。

- 既定の字数は下限ではない。依頼に字数が無いとき、既定に届かせるための継ぎ足しはしない。
- 継ぎ足しや差し替えをしたら、頭から通して一度読み直し、物の在りか・済んだ作業・経過した時間を追って確かめる。

## ラウンド 9: その 2 点を足したあとの連載（2 試行）

| 依頼 | 試行 | gpt-6-astra | Gemini 3.1 Pro | Claude Sonnet 5 |
|---|---|---|---|---|
| 連載第 12 話 | 1 | 順序不安定 | with | with |
| 連載第 12 話 | 2 | with | with | with |

スキルなし版が提示順によらず選ばれた対は無くなった。作業記録では、試行 2 は 1,529 字で書き終えて継ぎ足しをせず、試行 1 は 1,871 → 2,327 → 2,429 字の 2 回の継ぎ足しだった（ラウンド 8 は 6 回）。同じ依頼を 3 ラウンド続けて直しているので、この依頼への過剰適合の可能性は残る。足した 2 点は、依頼に固有のことを書いていない一般の決まりにしてある。

Sonnet の判定 1 件は、最終行を見出しの形（`## 選好: B`）で書いたため、最初は読み取れず失敗として記録された。読み取りを直して（見出し・箇条書き・太字の飾りは可）、その判定だけ取り直した。

## 所要時間を縮める試み（効果を確認できなかった）

スキルあり版は、どのラウンドでも 1 件 2〜9 分・0.3〜1.1 ドル・道具 8〜41 回（スキルなし版は 15〜35 秒・約 0.04 ドル・道具なし）。作業記録から見えた周回の形は 2 つ。

- 字数の目安があると、初稿が目安の 55〜65% で出て（1,500 字の依頼に 800〜990 字）、そこから 100〜300 字ずつ継ぎ足しては測り直す。
- `novel_lint.py` を 3〜8 回かける。

試したことと結果:

| 試したこと | 結果 |
|---|---|
| スキルの本文に「書く前に場面ごとの字数を割り振る」「直しと測り直しは 1 回」（ラウンド 4） | 道具の回数に差は見えない |
| `novel_lint.py --range` と、出力の最後の「次にやること」（ラウンド 6） | 差は見えない。`count_chars.py` を別に走らせない実行は増えたが、約 1,500 字の指定で下限ぴったり（1,350 字）まで 4 字単位で合わせにいく例が出た → 約 N 字は下限を 3% まで割っても範囲内とした |
| 「初稿は目安の 1.3 倍のつもりで」「不足の 1.3 倍を一度に書き足す」（ラウンド 7） | 初稿は 800〜990 字のまま。書き足しも、求めた量の 3 割ほどしか足さない。検証レビュー 15 の指摘（水増しの指令になる）もあり、削除した |
| 字数を行数に直して持たせる（1,500 字は約 50 行。ラウンド 8） | 初稿は 880〜910 字のまま。削除した |
| 既定の字数は下限ではない（ラウンド 9） | 字数の指定が無い依頼では、継ぎ足しが 6 回 → 0〜2 回に減った |

Sonnet 5 は、求めた字数の半分前後しか一度に書かない傾向があり、文言では動かなかった。字数の指定がある依頼での周回は未解決。`--range` と「次にやること」は、害が見えず、測り直しの道具が 1 つで済むので残してある。

## 道具と足場の変更（このラウンドのあいだ）

- `scripts/novel_lint.py`: `--range`、「次にやること」、案内 C09（割合・内訳・合計の言及）。
- `evals/gateway.py`: 検証レビュー 15 を受けて、鍵の伏せ字をすべての出力の経路に、既定で通す python をスキルの検査スクリプトだけに、時間切れで子孫のプロセスごと終了、保証できない範囲の明記。ラウンド 6〜9 の生成は、この修正の前の設定（任意の python を許可）で行った。修正後の設定で入れ子の Claude Code が支障なく動くことは、1 件の生成で確かめた（下の「記録」）。
- `evals/run_blind_eval.py`: 前置きのハッシュの記録と照合（記録の無い旧応答は、generate の再開で使い回さない）。判定の最終行の読み取りで、見出しの形を許す。

## 言えること・言えないこと

- 言える: スキルの修正に使っていない 5 依頼で、スキルなし版が提示順によらず選ばれた対は、3 つの判定役のどれにも無かった。連載の依頼では、条件の照合・既定の字数・通読の 3 点を足したあと、スキルなし版が提示順によらず選ばれた対が無くなった。
- 言えない: 勝率。一般的な品質の向上。どの修正がどの選好を動かしたか。所要時間の改善（字数の指定がある依頼では、確認できていない）。
- 判定役どうしの不一致は、このラウンドでも大きい。Sonnet は順序不安定が多い。1 つの判定役の結果を結論にしないこと。
